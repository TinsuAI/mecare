## Phần 4: Lessons Learned

### Làm tốt — Tiếp tục giữ

1. **Documentation-as-code với contract tests** — Epic 7 thiết lập pattern mới: runbook sections được verify bằng text assertion tests, không phải manual review. Tests 18.x–20.x sẽ catch runbook regressions nếu ai sửa docs sau này. Scalable approach cho documentation epics.

2. **QA gap-fill phase tái khẳng định giá trị** — 14/48 tests mới (29%) do QA gap-fill thêm sau dev session. Gaps được tìm: missing keyword refs, weak assertions, AC coverage holes. Pattern: Dev builds tests → QA finds gaps → gaps filled → coverage tốt hơn.

3. **Scope discipline** — Cả 3 stories giữ đúng "docs + tests only, không runtime code mới." Không có scope creep. Mọi deferred items từ Epic 6 được giải quyết mà không vượt scope.

4. **Relay flow documented end-to-end** — Story 7.2 text art diagram của relay flow (`Khách → Zalo → zalo-bridge → OpenClaw → EscalationCase → ...`) là tài liệu đầu tiên trace toàn bộ path từ trigger đến resolved. Giá trị cao cho debugging production incidents.

5. **Contract test coverage của n8n workflow JSON** — Tests 20.3–20.8 verify node IDs và jsCode content trong MC-Handle-InboundReply.json và MC-Schedule-DueReminders.json. Nếu ai refactor n8n và đổi node ID, tests sẽ fail immediately.

### Cần cải thiện

1. **Sprint-status sync vẫn bị miss** — Pattern từ Epic 6 chưa được fix: Story 7.2 review phải auto-fix story status từ `ready-for-dev` → `done`. Dev workflow cần explicit checklist: "update sprint-status → done TRƯỚC KHI mark tasks complete." Tái diễn lần thứ 3 (Epic 6 x2 + Epic 7 x1).

2. **Test assertion strength** — Hai tests (18.4 dùng `||` fallback, 19.8 dùng trivial step-count markers) được review flag là weak. Contract tests cần exact keyword assertions thay vì OR fallbacks khi runbook content đã confirmed stable. Document expected keywords trong dev notes để dev không dùng broad fallbacks.

3. **version/updated_by/approved_at auto-fill** — Deferred từ Epic 6, vẫn chưa có AC trong Epic 7. Nếu project mở rộng, đây là UX gap cho chủ nhà thuốc (phải set manually). Documented nhưng không block go-live.

4. **Duplicate condition trong test** — Story 7.2 test 19.14 có `warmup.sh || warmup.sh` (same condition cả hai nhánh) — caught bởi review nhưng nên catch bởi linter hoặc peer review trước. ESLint rule `no-duplicate-case` / `no-identical-branches` sẽ catch ngay.

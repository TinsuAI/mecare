## Phần 4: Lessons Learned

### Làm tốt — Tiếp tục giữ

1. **Zero-code epic pattern** — toàn bộ FR-14+FR-15 delivered qua JSON views + tests; không cần touch n8n, OpenClaw, hay Express. Architecture constraint "no frontend v1" được giữ 100%.

2. **Tenant isolation pattern nhất quán** — Story 6.1 thiết lập, 6.2 áp ngay, 6.3 follow. Pattern: pharmacy_id hidden trong view JSON + description note → onboarding runbook filter per tenant. Zero drift across 3 stories.

3. **Contract test structure scalable** — 11 describe groups (test 1–17), 821 total tests, Node.js built-in runner, loadView() helper pattern. Không cần refactor test infrastructure qua 7 epics.

4. **QA gap-fill phase** — thêm 10+ tests sau mỗi story, catch description content và system field visibility gaps mà spec AC không explicit. Đặc biệt có giá trị với Story 6.3 (nhiều hidden system fields).

5. **0 CRITICAL, 0 HIGH** — lần đầu tiên một epic hoàn thành với zero HIGH findings. Phản ánh tính chất "static data" (JSON views) và coverage của contract tests.

### Cần cải thiện

1. **Sprint-status sync missed twice** — Story 6.1 và 6.2 cả hai bị review mới phát hiện sprint-status còn ready-for-dev. Dev workflow cần checklist step: "update sprint-status → done before marking story complete."

2. **Unstaged files sau QA session** — Story 6.2 và 6.3 cả hai có QA gap-fill tests unstaged khi dev session kết thúc. Dev cần chạy `git status` sau QA phase trước khi close session.

3. **AC text precision** — Story 6.2 AC7 nói "≥790 tests" nhưng thực tế delivered 792. AC nên specify exact count hoặc dùng "≥N" cẩn thận hơn để không dễ bị stale.

4. **Workspace visibility deferred** — "chỉ thấy 2 bảng" (chủ thuốc chỉ thấy MessageTemplates + FaqEntries) là Baserow Admin UI permission; không thể deliver qua view JSON. Story 7.1 phải nhận rõ item này.
